# TiXL bridge workflow

- Before downloading, installing, configuring, or running either application for a new user, read and follow [`.agents/README.md`](.agents/README.md). It is the canonical cross-agent onboarding guide; do not skip the end user's first-run choices, especially the TiXL username/root namespace.
- Before operating or troubleshooting the bridge, read and follow [`.agents/skills/blender-tixl-bridge/SKILL.md`](.agents/skills/blender-tixl-bridge/SKILL.md). It is the capability map and execution playbook for Blender MCP, the TiXL debug protocol, and the bridge's TiXL operators.
- For repeatable work, also load the focused skill: [offline sync](.agents/skills/blender-tixl-offline-sync/SKILL.md), [graph edits](.agents/skills/blender-tixl-graph-edit/SKILL.md), [dynamic layout](.agents/skills/blender-tixl-graph-layout/SKILL.md), or [audio and beat-linked visuals](.agents/skills/blender-tixl-audio/SKILL.md). These procedures use the generated capability report and support manual/offline preparation without a live TiXL socket; agent-driven Blender and TiXL actions still use their required bridges.
- After upgrading Blender, Blender MCP, TiXL, the TiXL debug bridge, or this add-on, read and follow [`.agents/skills/blender-tixl-release-refresh/SKILL.md`](.agents/skills/blender-tixl-release-refresh/SKILL.md). It owns capability regeneration, release screenshots, README claims, package rebuilding, and upgrade verification.
- Keep the root `README.md` a short human landing page: project purpose, main features, the plug-in-only and agentic-workspace modes, minimal quick start, documentation links, and important limitations only. Put setup and procedures in `docs/USER_GUIDE.md`, the human explanation of workspace benefits in `docs/AGENTIC_WORKFLOW.md`, technical behavior in `docs/BRIDGE_REFERENCE.md`, and agent-only instructions under `.agents/`.
- Capability discovery is non-AI, one-shot automation owned by the Blender add-on. It runs on add-on install/update, add-on registration, and before sync, and can be started manually with **Refresh agent capabilities**. Do not install a scheduled task, watcher, or background service. Agents read [`.agents/CAPABILITIES.md`](.agents/CAPABILITIES.md); they do not manually manufacture its probe inputs.
- Use the official Blender MCP TCP extension for every Blender action, inspection, script execution, scene load, save, and verification. Connect to its configured host and port (normally `localhost:9876`), even when the agent runtime does not expose a named Blender tool. In that case, use the repository's `BlenderTcpExtensionClient` in `.agents/capability_automation.py` to send requests directly to the extension; absence of a named tool alone is not a reason to stop. Confirm a live response before acting, and do not replace the extension with Blender CLI or UI automation.
- Use the TiXL debug bridge for every TiXL launch, project selection, graph inspection, output evaluation, and screenshot. The client is `blender_tixl_bridge/source/tixl_bridge.py`; the normal debug port is 9042.
- After TiXL's first-run username/root namespace and operator project are configured, do not ask the user to close TiXL for routine syncs. For an agent-launched session with no subsequent editor mutations or known pending save, close it through the TiXL debug bridge's `shutdown`, confirm the process exits, then run the installation and relaunch through the bridge. The debug protocol does not report unsaved edits: never infer a clean state merely from `getContext`, a paused timeline, or a successful screenshot. If editor work may be unsaved, ask the user to save that work only when needed, then perform the close yourself. Do not discard known or uncertain user edits.
- Never use Computer Use, screen automation, simulated mouse/keyboard input, or generic UI automation for Blender or TiXL. If Blender MCP or the TiXL debug bridge cannot perform a required action, stop and ask the end user to complete that step manually.
- After changing a loaded `.t3` or `.t3ui` graph structure on disk, TiXL's `reload` command can leave the old graph in memory. Preserve any editor work, then use the clean-session shutdown and bridge restart workflow before claiming the new graph is visible.
- When a generated or user-edited TiXL graph needs a readable layout, follow [the graph-layout agent rules](.agents/skills/blender-tixl-bridge/references/graph-layout.md). Arrange from actual connections, preserve every node and edge, keep backups outside `Symbols`, and check the rendered output after the restart. Apply the same procedure to new or growing graphs rather than hard-coding one scene's coordinates.
- Keep generated Blender import data separate from user-edited TiXL home graphs and TimeClips. Check the rendered output as well as graph connections after a sync.
- Load task references through the operational router; read `CAPABILITIES.md` for coverage and warnings, and `CAPABILITIES_DETAIL.md` only for full inventories and schemas. Onboarding is for new users; release refresh is for upgrades. Review unclassified methods before use.
- The current add-on package is `blender_tixl_bridge`; `tixl_blender_bridge` is a legacy migration name. Preserve local notes such as `.agents/AGENTS.md`; do not rewrite or package them to resolve old naming/routing guidance. For package changes rebuild the ZIP, run the verified checkout installer through Blender MCP, and verify saved preferences in a fresh Blender process launched through MCP. Keep personal paths/preferences out of commits.
