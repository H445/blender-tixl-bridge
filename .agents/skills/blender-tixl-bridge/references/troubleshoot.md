# Diagnose stale or blank output

1. Through Blender MCP check the saved source path, camera/markers, collections/world JSON, enabled add-on, operator-project/editor paths and connection mode. Inspect `latest.log`, generation commit/recovery, cache hashes/manifests and generated project path using filesystem tools. Load [Blender recipes](blender.md) only when configuration/preflight needs correction.
2. Through the debug client call `getVersion`, then capture context/view. Verify the intended project, time, playback and pinned output. Read `getGraphState` for missing children/connections and relevant path inputs. An unavailable editor can be launched using the configured executable with the debug-server flag when authorized; verify readiness through the client. For a required restart, use the clean-session shutdown workflow in [Sync](sync.md); preserve unsaved work.
3. Pause, pin Output target, set a meaningful source time, pump three frames and capture output. Read incremental `getLogTail(minLevel="warning")` and `getMetrics`. Inspect geometry/materials/camera and compare a known reference; an existing PNG is insufficient. Check every world and both sides of cuts when selection/timing is suspect.
4. For graph-path problems consult [operator semantics](operators.md); for unrecognized API signatures consult [protocol details](protocol.md) and `.agents/CAPABILITIES_DETAIL.md`. Unknown/unclassified methods require handler review before use.
5. If loaded `.t3` or `.t3ui` structure changed on disk, preserve user work and restart through the bridge; `reload` can leave old instances. For code-only reload, read back graph/output afterward. Preserve generated/user-owned separation and never overwrite Home/TimeClips to repair an import.
6. Restore original project, graph view, selection, pin, time and playback (playing mode before exact speed). Report the failing layer and evidence. Unsupported API/bootstrap steps need a manual user handoff, never UI automation.

For stale/missing capabilities load [discovery details](discovery.md). Refresh through the add-on's one-shot operator; verify both generated files and logs. Do not fabricate inputs, install a watcher, or infer safety from method names.

For a compact repeatable protocol snapshot, retained-log follow, or explicitly requested state-restoring output capture, see [bounded diagnostics](diagnostics.md). The default CLI modes do not inspect a graph during log follow and do not capture or change playback/time unless capture times are supplied.
